Factory Inventory Management System

An architecture overview of the demo app: a Vue 3 single-page app that calls a Python FastAPI service. The service filters in-memory data loaded from JSON files when it starts. There is no database, no real authentication and no write path for core data.

Data flow: changing a filter on the Dashboard

  1. The user picks a value in FilterBar (Time Period, Warehouse, Category or Order Status). This writes to one of four refs declared at module level in useFilters.js. Every component shares those refs, so this works as a simple singleton store.
  2. Each view runs watch() on those four refs. On any change it calls loadData(). It also calls loadData() once in onMounted.
  3. getCurrentFilters() maps the UI state to {warehouse, category, status, month}. api.js leaves out any value set to 'all' and builds the query string.
  4. The Dashboard sends four requests in parallel with Promise.all: /dashboard/summary, /orders, /inventory and /backlog. The calls go cross-origin straight to port 8001. Vite has no proxy configured, so the server's CORS setting allows them.
  5. FastAPI runs apply_filters(). Warehouse must match exactly, and category and status match without regard to case. For orders it also runs filter_by_month(), which looks for YYYY-MM as a substring of order_date or expands a Q1-2025 quarter key. All of this works on plain Python lists in memory.
  6. The summary endpoint computes its KPIs on each request: inventory value, low-stock count, pending orders and total order value. FastAPI then serializes the result, checking it against the Pydantic response_model where the endpoint declares one.
  7. The view stores the raw JSON in refs. Computed properties work out chart series, top products and revenue goals ($800K a month, or $9.6M year to date). formatCurrency() converts amounts to yen at a fixed rate of 150 when the locale is ja.

Gaps and caveats found in the code

Client calls endpoints the server doesn't have. api.js calls /api/tasks (GET, POST, PATCH and DELETE) and /api/purchase-orders (GET and POST), but main.py defines neither, so those requests get a 404. App.vue uses the tasks calls.
The Backlog view isn't routed. views/Backlog.vue exists, but main.js doesn't register it. Backlog data appears only on the Dashboard.
Filtering is uneven. Inventory has no time dimension, so the month filter doesn't apply to it. Demand, backlog, spending and reports ignore every filter. total_backlog_items in the summary is never filtered.
Demo-only settings. The API base URL is hard-coded, CORS accepts any origin, the user in useAuth is a mock, the yen rate is fixed, and in-memory data resets on every restart.
